## 3. ขอบเขต 20 พ.ย.

### ทำ
1. **Wallet + บัญชีแยกประเภท (ledger)** — ลูกค้า / Part-Time / บริษัท (พาร์ทเนอร์เตรียมโครงไว้)
2. **ลูกค้าเติมเงิน** QR + สลิป → Slip2Go ผ่านแล้วเข้ากระเป๋าอัตโนมัติ · ไม่ผ่านเข้าคิวแอดมิน
3. **หน้าแรกแสดง Part-Time จริง** (ผ่าน KYC + อบรม + เปิดรับงาน) แทนตัวอย่าง 20 คน · โปรไฟล์จริง
4. **การจอง** วัน · เวลา · 3/5 ชม. · สถานที่ (รวมสปาพาร์ทเนอร์) · กิจกรรม → ตัดจากกระเป๋าเข้า "เงินพักไว้"
5. **Part-Time รับ / ปฏิเสธงาน** (หมดเวลาตอบ = คืนเงินอัตโนมัติ) · ตาราง / หน้างาน / ตัวนับ ใช้ข้อมูลจริง
6. **แชทจริง** ลูกค้า ↔ Part-Time (realtime · กันเบอร์/LINE/ลิงก์ · ข้อความตอบกลับเร็ว/อัตโนมัติที่ทำไว้แล้ว)
7. **วันนัด** เช็กอินถึงจุดนัด · SOS · จบงาน (ทั้งสองฝ่ายยืนยัน / ยืนยันอัตโนมัติ) · รีวิว
8. **แบ่งเงินเมื่อจบงาน** ตาม % ขั้นส่วนแบ่ง → Part-Time "รอปล่อย" → 24 ชม. → "ถอนได้"
9. **ถอนเงิน** Part-Time กดถอน → **ถอนอัตโนมัติ** รอบ 10:00 (ไฟล์โอนกลุ่มของธนาคาร + ปุ่มยืนยันโอนแล้ว · พร้อมต่อ API ธนาคารเมื่อได้รับอนุมัติ) · ใบเสร็จ + 50 ทวิ PDF อัตโนมัติ
10. **แจ้งเตือน** งานใหม่ · ตอบรับ · ข้อความใหม่ · ใกล้ถึงเวลานัด · เงินเข้า (web push + LINE OA ถ้าได้ token)
11. **พาร์ทเนอร์ทดสอบได้** สปาเป็นสถานที่นัด · พอร์ทัลพาร์ทเนอร์เห็นการจองที่เข้าร้าน
12. **หลังบ้าน** การจอง · เงินพักไว้ · คิวเติมเงิน · คิวถอน · ปรับยอดพร้อมเหตุผล · กติกายกเลิก (ตั้งค่า) · รายงานกระทบยอดรายวัน

### ไม่ทำรอบนี้ (ย้ายไป ธ.ค.–ก.พ.)
ยืนยันตัวตนลูกค้า · ระบบตัดบัตร · โทรซ่อนเบอร์ (ใช้แชท) · ระดับสมาชิกลูกค้า · แผนที่ติดตามตำแหน่งแบบ live (ใช้เช็กอิน + แชร์ตำแหน่งครั้งเดียว) · ราคาร้านพาร์ทเนอร์ / mark-up · สปอนเซอร์ · พอร์ทัลพาร์ทเนอร์ส่วนรายงาน / ป้ายแบรนด์

## 4. สถาปัตยกรรมเงิน (Wallet / Ledger)

### หลักการ
- **ทุกการเคลื่อนไหวของเงิน = 1 ธุรกรรม (`wallet_tx`) ที่มีรายการบัญชีคู่ (`wallet_entries`) ผลรวมเป็น 0 เสมอ**
- รายการ **แก้/ลบไม่ได้** (append-only) · แก้ผิดด้วยรายการกลับ (reversal) พร้อมเหตุผล
- ยอดคงเหลือ = ผลรวมรายการ (มี view + cache ที่ตรวจทานได้) — ไม่มีการ "เขียนทับยอด"
- ทุกคำสั่งเงินทำใน **Postgres function เดียว** (transaction + `select … for update`) และมี **idempotency key** กันกดซ้ำ
- เงินเป็น **สตางค์ (bigint)** ไม่ใช้ทศนิยม

### กระเป๋าและช่องเงิน
| เจ้าของ | ช่อง (bucket) | ความหมาย |
|---|---|---|
| ลูกค้า | `available` | ใช้จองได้ |
| ลูกค้า | `held` | กันไว้ระหว่างรอ Part-Time ตอบรับ |
| Part-Time | `pending` | รายได้จากงานที่จบ รอครบ 24 ชม. |
| Part-Time | `available` | ถอนได้ |
| Part-Time | `withdrawing` | อยู่ในรอบโอน |
| บริษัท | `escrow` | เงินพักไว้ของการจองที่ยืนยันแล้ว |
| บริษัท | `revenue` | ส่วนของแพลตฟอร์ม + ค่าธรรมเนียมถอน 3% |
| บริษัท | `wht_payable` | ภาษีหัก ณ ที่จ่ายรอนำส่ง |
| บริษัท | `bank` | เงินจริงในบัญชีธนาคาร (ใช้กระทบยอด) |
| พาร์ทเนอร์ | `available` | (เตรียมไว้ ยังไม่เปิด) |

### ทางเดินเงิน
```
เติมเงิน            bank            → ลูกค้า.available        (Slip2Go ผ่าน / แอดมินอนุมัติ)
ส่งคำขอจอง          ลูกค้า.available → ลูกค้า.held
Part-Time ตอบรับ    ลูกค้า.held      → บริษัท.escrow
ปฏิเสธ / หมดเวลา    ลูกค้า.held      → ลูกค้า.available
จบงาน (แบ่งเงิน)    บริษัท.escrow    → PT.pending (x%) + บริษัท.revenue (100−x%)
ครบ 24 ชม.          PT.pending       → PT.available
ขอถอน               PT.available     → PT.withdrawing
โอนสำเร็จ           PT.withdrawing   → bank (สุทธิ) + บริษัท.revenue (3%) + บริษัท.wht_payable (3%)
โอนไม่สำเร็จ        PT.withdrawing   → PT.available
ยกเลิก/ไม่มาตามนัด  ตามกติกา (ตั้งค่า) หรือแอดมินตัดสิน → รายการคืน/โอนพร้อมเหตุผล
ลูกค้าขอถอนคืน      ลูกค้า.available → bank (แอดมินอนุมัติ)
```
x% = ขั้นส่วนแบ่งตามจำนวนเคสของ Part-Time ในเดือนนั้น (หน้า "ราคาและส่วนแบ่ง") · ทิปให้ Part-Time ตาม % ที่ตั้งไว้

### ถอนอัตโนมัติ
- **รอบอัตโนมัติ** (Vercel Cron 10:00 ทุกวัน) รวมคำขอถอน → สร้าง `payout_batch`
  - **ขั้น 1 (20 พ.ย.):** สร้างไฟล์โอนเงินแบบกลุ่ม (bulk payment) ตามรูปแบบธนาคารบริษัท → แอดมินอัปโหลดในแอปธนาคาร → กด "โอนแล้ว" ครั้งเดียว ระบบปิดทุกรายการ + ออกเอกสาร
  - **ขั้น 2 (ธ.ค.–ก.พ.):** ต่อ API ธนาคาร/ผู้ให้บริการโอนเงิน → ไม่ต้องมีคนกด (ใช้โครงเดียวกัน แค่เปลี่ยนตัวส่ง)
- เกินวงเงินอัตโนมัติ / บัญชีเพิ่งเปลี่ยน < 48 ชม. / มีเรื่องร้องเรียนค้าง → พักให้แอดมินอนุมัติ
- ใบเสร็จรับเงิน/ใบกำกับภาษี (ค่าธรรมเนียม 3%) + หนังสือรับรองหัก ณ ที่จ่าย 50 ทวิ ออกอัตโนมัติ เก็บ 30 วัน (ตามบอร์ด EarningDocs)

### การตรวจสอบ
- รายงานกระทบยอดรายวัน: ผลรวมทุกกระเป๋า = 0 · `bank` ตรงกับยอดเติม−ยอดโอน · แจ้งเตือนแอดมินถ้าไม่ตรง
- บันทึกทุกครั้งที่แอดมินปรับยอด (ใคร · เท่าไร · เหตุผล · อ้างอิง)

## 6. แผนรายสัปดาห์ (milestones)

### M0 · หน้าขายพร้อมรับสมัคร — 15–19 ต.ค. (ครบกำหนด 20 ต.ค.)
- ทดสอบสมัครจริงบนเว็บจริง 1 รอบ (ชำระ → KYC → บัญชี → สัญญา → สำเร็จ → แอดมินเห็น) แล้วลบข้อมูลทดสอบ
- ตัดสินใจ: รับสมัครก่อน 20 ต.ค. ได้ไหม → ถ้าไม่ ทำ gate ตาม `OPEN_AT`
- ยืนยันบัญชีรับเงินใน QR · ข้อความวันเปิดให้บริการ (30 → 20 พ.ย.)
- เช็ก env บน Vercel: `SLIP2GO_API_SECRET` · `RESEND_API_KEY` + `ADMIN_NOTIFY_EMAIL` · `GOOGLE_SHEETS_WEBHOOK_URL` · (ถ้ามี) `THAIBULKSMS_*`
- ทดสอบจริงในแอป LINE บน iPhone + Android · มือถือจอเล็ก (iPhone SE)

### M1 · ฐานเงิน + ข้อมูลจริง — 16–24 ต.ค.
- SQL migration: wallet + booking + messages + notifications (+ สคริปต์ rollback)
- `lib/wallet`: ฟังก์ชันเงินทั้งหมดเป็น Postgres function + ชุดทดสอบ (ผลรวม = 0 · กันซ้ำ · ยอดติดลบไม่ได้)
- ลูกค้า: สมัคร/ล็อกอิน (มีแล้ว) + หน้ากระเป๋าเงิน + เติมเงิน QR + สลิป + Slip2Go เข้ากระเป๋าอัตโนมัติ
- แอดมิน: คิวเติมเงิน (อนุมัติ/ปฏิเสธ) · ดูยอดทุกกระเป๋า · ปรับยอดพร้อมเหตุผล
- ข้อมูลจริง: ตาราง/มุมมอง "Part-Time ที่เปิดรับงาน" จากผู้สมัคร (ผ่าน KYC + อบรม + ไม่พักงาน) → หน้าแรก + `/p/[id]` ใช้ข้อมูลจริง (คงตัวอย่างไว้จนกว่าจะมีคนจริง)

### M2 · การจอง + แชท — 25–31 ต.ค.
- ลูกค้า: ฟอร์มจอง (บอร์ด C-Booking / C-Checkout) → ตัดจากกระเป๋า (held) · หน้ารายการจองของฉัน
- Part-Time: งานเข้า (บอร์ด P-Incoming) ตอบรับ/ปฏิเสธพร้อมเหตุผล · หมดเวลา 30 นาที = คืนเงินอัตโนมัติ (cron)
- ตาราง / งาน / ตัวนับของ Part-Time ใช้การจองจริง
- แชท realtime (บอร์ด C-ChatRoom) · กันช่องทางนอกแอป · ข้อความอัตโนมัติ/ตอบกลับเร็วใช้ค่าที่ Part-Time ตั้งไว้
- แจ้งเตือน: web push + กล่องแจ้งเตือนในแอป (+ LINE OA ถ้าได้ token)

### M3 · วันนัด + เงินออก — 1–7 พ.ย.
- วันนัด (บอร์ด P-Job / C-Tracking): เช็กอินถึงจุดนัด · SOS (มีปุ่มแล้ว ต่อเข้าการจอง) · จบงาน · ยืนยันอัตโนมัติถ้าไม่มีใครค้าน 12 ชม.
- แบ่งเงิน → pending → 24 ชม. → available (cron)
- รีวิว (บอร์ด C-Complete / P-Reviews) · คะแนนเฉลี่ยบนโปรไฟล์
- หน้ารายได้/ถอนเงิน/เอกสารภาษีของ Part-Time ใช้ยอดจริง
- ถอนอัตโนมัติ ขั้น 1: cron 10:00 → payout batch → ไฟล์โอนกลุ่ม → ยืนยันโอน → PDF ใบเสร็จ + 50 ทวิ
- แอดมิน: การจองทั้งหมด · เงินพักไว้ · ตัดสินยกเลิก/ไม่มาตามนัด · คิวถอน · รายงานกระทบยอดรายวัน
- กติกายกเลิก: หน้าตั้งค่าในหลังบ้าน (ค่าเริ่มต้น = แอดมินตัดสิน)

### M4 · พาร์ทเนอร์ + ทดสอบรวม — 8–14 พ.ย.
- ลูกค้าเลือกสปาพาร์ทเนอร์เป็นสถานที่นัด (บอร์ด SpaList / SpaDetail) จากข้อมูลพาร์ทเนอร์ที่มีอยู่
- พอร์ทัลพาร์ทเนอร์: เห็นการจองที่เข้าร้าน · ยืนยันห้อง
- ทดสอบรวมทั้งระบบโดยทีมงาน (เล่นเป็นลูกค้า + Part-Time ทดสอบ): ชุดทดสอบอัตโนมัติ e2e + เช็กลิสต์มือ
- ทดสอบเงิน: ทุกเส้นทางในข้อ 4 · กดซ้ำ · พร้อมกันหลายคน · กระทบยอด
- ความปลอดภัย: สิทธิ์เข้าถึงทุก API · rate limit · ข้อมูลส่วนตัวไม่หลุดในแชท/รีวิว
- ทดสอบในแอป LINE + มือถือจริง

### M5 · เปิดใช้งาน — 15–20 พ.ย.
- 15–16 อบรม + ถ่ายรูป → 17 พ.ย. นำ Part-Time จริง + รูปเข้าระบบ · เปิดสถานะรับงาน · ปิดข้อมูลตัวอย่าง
- 17–19 พ.ย. ทดสอบจองจริงกับ Part-Time จริง (เงินจริงยอดเล็ก) · แก้ปัญหา
- 19 พ.ย. เช็กลิสต์เปิดระบบ (ข้อ 8) · สำรองฐานข้อมูล
- **20 พ.ย. เปิดให้ลูกค้าใช้จริง** · เฝ้าระบบ 72 ชม.แรก

## 7. การทดสอบ
- **ชุดทดสอบอัตโนมัติ** (มีแล้วสำหรับสมัคร Part-Time 34 + ลิงก์เชิญ 17 ข้อ) → เพิ่ม: wallet · จอง · แชท · วันนัด · ถอน
- **โหมดเดโม** (`mb-app-demo`) ใช้ทดสอบโดยไม่แตะฐานข้อมูลจริง
- **staging**: โปรเจกต์ Supabase แยกสำหรับทดสอบเงิน (แนะนำ) หรือ schema ทดสอบ
- ทดสอบมือก่อนเปิด: iPhone + Android · Chrome + แอป LINE · จอคอม

## 8. เช็กลิสต์เปิดระบบ (19 พ.ย.)
- [ ] รายงานกระทบยอดตรง 3 วันติด · [ ] สำรองฐานข้อมูล + ทดลองกู้คืน
- [ ] env ครบ (Slip2Go · อีเมล · push · LINE OA · cron secret) · [ ] cron ทำงาน (หมดเวลาตอบรับ · ปล่อยเงิน · รอบถอน)
- [ ] Part-Time จริง ≥ 1 คนเปิดรับงาน มีรูปจริง · [ ] ปิดข้อมูลตัวอย่างบนหน้าแรก
- [ ] แอดมินอย่างน้อย 2 คนเข้าหลังบ้านได้ + รู้ขั้นตอน (คิวเติมเงิน · คิวถอน · ตัดสินเคส · SOS)
- [ ] ช่องทางติดต่อฉุกเฉินของทีมงานพร้อม

## 10. ความเสี่ยง
| ความเสี่ยง | ผล | ทางกัน |
|---|---|---|
| Wallet ผิดพลาด (เงินจริง) | สูง | ledger บัญชีคู่ · Postgres function · ทดสอบอัตโนมัติ · กระทบยอดรายวัน · ทดลองเงินจริงยอดเล็กก่อน |
| SQL migration รันช้า | แผนเลื่อน | ส่งไฟล์ภายใน 20 ต.ค. · ทำงานส่วนอื่นในโหมดเดโมคู่กัน |
| Part-Time จริงเข้าระบบช้า (หลังอบรม 16 พ.ย.) | ทดสอบจริงสั้น | ทดสอบรวมให้เสร็จ 8–14 พ.ย. ด้วยบัญชีทดสอบ |
| ธนาคารไม่มี bulk payment | ถอนต้องโอนมือ | หลังบ้านมีหน้าโอนทีละรายการ + ปุ่มยืนยัน สำรองไว้ |
| แจ้งเตือนไม่ถึง (iOS web push ต้องติดตั้งเว็บแอป) | งานหลุด | แจ้งเตือนในแอป + LINE OA + หน้าหลังบ้านมีงานค้าง |
| Slip2Go ล่ม/ตีกลับ | เติมเงินช้า | คิวแอดมินอนุมัติด้วยมือ |
